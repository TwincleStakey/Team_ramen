[9/9 개발 세션 — 조리 화면 픽셀 통일 + 연출 3건 + 그레인]

배경: 조리 화면이 조잡해 보이고 글씨가 안 읽힘. 원인은 필터가 아니라 (1) 픽셀 배율 혼재 (2) 픽셀 폰트를 AA로 그림 (3) 평면 흰 라벨 20개. 아래 0단계를 먼저 하고, 그 다음 연출과 그레인.
기획서 v1.2 규칙(수량·보상·판정)은 어느 항목도 건드리지 않는다. 전부 표현만.

────────────────────────────
0단계. 픽셀 규칙 세우기 (가장 먼저)
────────────────────────────
0-1 폰트 교체
- 얇은 물마루(ThinMulmaru) → 갈무리(Galmuri) 11 (OFL, galmuri.quiple.dev). 획이 2px라 읽힘
- 라벨·상단바: legacy Text 유지하되 fontSize = 11 × 정수배(33 또는 44). 다른 크기 금지
- 팝업(TMP): SDF 에셋 대신 Font Asset Creator에서 Render Mode = RASTER, Sampling 11, 아틀라스 Filter = Point. 크기는 33/44/55만
- 검증: 게임 뷰 100%에서 글자 가장자리에 회색 픽셀이 없어야 함

0-2 라벨 정리
- 재료통 옆 흰 라벨(시오·쇼유·돈코츠·멘마…·얇은면·굵은면·향미유·시치미·육수) 전부 제거. 그림이 이름이다
- 남기는 텍스트: 상단바(일차, 누적 수익), 제출하기, ? 버튼뿐
- 재료 이름은 재료통에 마우스 호버 시 픽셀 팻말 1개로만 표시 (RamenLayoutBuilder에 호버 팻말 프리팹 하나)

0-3 배율 통일
- 기준 격자 640×360, 화면 배율 3배. 모든 스프라이트 3배. 그릇도 6배 → 3배(384px)
- 그릇이 작아 보이면 기획자에게 그릇 원본 192~256px 재요청 (아트 요청 항목). 그 전까진 3배로 간다
- 모든 RectTransform 위치를 3의 배수로 스냅. Slots 배열 좌표를 3배수로 정리
- 재료통 3배 × 7개가 세로에 안 들어가면 간격을 줄이지 말고 2열로

0-4 바닥과 그림자
- 배경: 나무 카운터 타일 1장 (임시로 64px 타일 A가 그림, Point, Repeat). 재료통·그릇 아래 2px 오프셋 단색 그림자 (소프트 섀도 금지)
- 상단바·제출 버튼: 9-slice 픽셀 패널 1장으로 통일

검증: 게임 뷰 스크린샷을 3배 확대해도 모든 픽셀이 3×3 정사각형이어야 함. 하나라도 2×2나 6×6이면 실패.

────────────────────────────
1단계. 손님 목소리 블립 (기획서 10.2 클릭식 대사창)
────────────────────────────
- 대사창 글자 출력 시 글자마다 짧은 톤(30~50ms) 재생. 자음·모음 구분 없이 한 글자 = 한 톤
- 말투(personaId) 15종 → 피치·간격 표. 예: Military 낮음·빠름, Child 높음·통통, Grandma 느림, Youtuber 높고 빠름, Otaku 낮고 불규칙
- 설계: AudioSource 1개 + 톤 클립 1개(사인파 wav 하나면 됨) + pitch만 바꿈. 클립 15개 안 만든다
- 어디에: 대사창 타이프라이터 코루틴이 A 소유(주문 화면). personaId는 OrderManager/DialogueScenario에서 읽기만
- 공백·문장부호는 무음. 마침표에서 120ms 쉼

────────────────────────────
2단계. 완벽한 한 그릇 플래시 (기획서 7.3)
────────────────────────────
- 정확도 100%일 때: 그릇+재료 전체를 1프레임 흰색 → 2프레임 원색 → 1프레임 흰색 → 원색. 알파 블렌딩 금지, Image.color 교체만
- 이어서 그릇 위 김 스프라이트 3프레임 + "완벽한 한 그릇!" 팻말(0-1 폰트, 44px). 팻말은 정수 픽셀로 8px 튀어올랐다 내려옴
- 트리거: SubmitRamen 뒤 EvaluateRamen 반환값이 10,000(=100%)일 때. RamenCalculator.LastAccuracy 읽기
- 효과음은 슬롯만 비워둠 (사운드는 나중)

────────────────────────────
3단계. 제출 후 1초의 기다림 (기획서 7.5, 14장)
────────────────────────────
- 이미 넣기로 한 OnCustomerServed 지연 코루틴에 연출을 얹는다. 순서:
  ① 그릇이 손님 쪽으로 정수 픽셀 슬라이드 (3px씩, 약 0.3초)
  ② 손님 자리에서 젓가락 3프레임 "후루룩" 3회 (기존 젓가락 스프라이트 재활용, 0.6초)
  ③ 그 다음에야 결과창(이모지·정확도) 표시
- 정확도 0%(필수 실패)면 ②를 건너뛰고 젓가락이 멈춘 채 "ㆍㆍㆍ" → 결과창
- 총 1.2초 이내. 클릭하면 스킵 가능

────────────────────────────
4단계. 그레인 (B 방식, 마지막)
────────────────────────────
- 캔버스는 Screen Space - Overlay 유지 (포스트프로세싱 안 쓴다)
- 캔버스 최상단(DragLayer보다 위)에 풀스크린 Image 1개 + 커스텀 셰이더. raycastTarget = false 필수
- 셰이더: uv를 floor(uv × float2(640,360)) / float2(640,360) 으로 스냅한 뒤 노이즈 샘플 → 알갱이가 게임 픽셀과 1:1. 노이즈 텍스처는 URP 패키지의 Medium01.png 그대로 사용, 프레임마다 오프셋
- 강도: 평소 0.06 (거의 안 보임). 폐기 순간 1프레임 0.4 + 화면 2px 정수 흔들림. 결과창 화남(69% 이하)일 때 0.15
- 대사창·주문서·결과창 텍스트 영역은 마스크로 제외 (가독성). 텍스트가 그레인 위에 오도록 형제 순서 조정
- 검증: 스크린샷 3배 확대 시 그레인 알갱이도 3×3. 1×1이면 스냅 실패

────────────────────────────
기획자에게 아트 요청 (개발과 무관하게 지금 보내도 됨)
────────────────────────────
- 그릇 원본 192 또는 256px (현재 128px을 6배로 써서 픽셀이 두 배 큼)
- 나무 카운터 타일 64px 1장
- 9-slice 픽셀 패널 1장 (상단바·버튼·팻말 공용)
- 손님 자리 실루엣 1장 (현재 살구색 사각형)
